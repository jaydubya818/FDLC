4. Run full local qualification, browser/operator checks, and independent security/data-integrity/architecture/simplicity review. Fix findings, preserve all Phase 2 evidence and record actual results with source hashes.
5. Use explicitly authorized live/deployed/controlled-publication targets. Without those, finish all independent work and present the exact missing boundary with concrete model/call/token/input/cost/evidence details when known. Never invent a model, account or approval.
6. Create focused cross-linked FDLC/Fab and MC implementation PRs after local qualification; use existing repository CI and review rules. Merge only after all applicable gates pass and repository authority allows. If merged, qualify exact fetched main from fresh installs and keep evidence separate.

## Design constraints

The full-site browser audit found existing duplicate complementary landmarks, unreadable inactive Mission Control tab metadata, and a horizontally scrollable comparison without keyboard focus. Fix only their accessible names, text contrast and keyboard access, then rebuild and rerun the affected browser routes. Preserve site layout and product positioning.

Fab owns read/plan/edit/check behavior and explicit completion, not lifecycle authority. MC owns state, admission, leases, verification, approval, publication and reconciliation. Preserve atomic tools, bounded context, exact checkpoints and explicit success/failure. Operator UI and agent observations use the same MC records; no second database, lease loop, approval service or Fab-only control plane. Local and isolated modes advertise measured capabilities independently. Mobile is a browser layout qualification, not a new native product. Self-modification, hosted multi-user Fab, new operating systems, autonomous merge and production deployment are outside Phase 3.
