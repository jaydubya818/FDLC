# FDLC Ecosystem Positioning

## What We’re Building

Refine FDLC.ai from a strong framework site into a clearly structured category and ecosystem narrative. The homepage should retain the memorable promise—“Build the factory that builds your software.”—then explain FDLC as the operating model and reference architecture for the factory itself.

The public story must distinguish FDLC, FDLC.ai, Mission Control, the Guide, FDLC Deploy, and FDLC Enterprise without implying that proposed commercial products are generally available.

## Why This Approach

A category-first structure is stronger than presenting FDLC primarily as an AI-governance concept or a collection of products. It gives technical and executive readers the same mental model while preserving evidence boundaries around current capabilities.

## Key Decisions

- **FDLC versus FDLC.ai:** FDLC is the lifecycle, engineering discipline, and reference architecture. FDLC.ai is the ecosystem advancing and applying it.
- **Homepage hierarchy:** Use the memorable promise as the H1 and the institutional category statement as supporting language and metadata.
- **Model separation:** Present the eight-stage FDLC lifecycle as canonical. Use the seven-step delivery loop only as an orientation layer; the detailed nine-artifact execution protocol remains canonical on the Framework page.
- **Ecosystem roles:** FDLC defines; Mission Control demonstrates; the Guide teaches; Deploy implements; Enterprise industrializes.
- **Claim discipline:** Keep Deploy and Enterprise labeled Design partner / Proposed. Describe enterprise scale as the design target, not a proven operating result.
- **Category boundary:** Governance is a property of the system. The category is the engineering and operation of autonomous software-production systems.

## Open Questions

- When should FDLC Enterprise graduate from proposed positioning to an announced product?
- Which legal entity and open-governance model will own the FDLC name, Specification, and certification authority?
- Which lighthouse outcomes can become the first public proof points?

## Next Steps

Update the core site narrative, preserve existing navigation and visual language, validate terminology and regressions, then republish the private release.
